# 公开仓库边界

本文用于约束 Visoraft 源码仓库的发布范围。公开仓库应保持可构建、可审查，同时不得包含真实业务数据、账号凭证和本地运行产物。

## 应提交

- React、Go、Python 源码及依赖锁文件。
- 数据库迁移、容器构建文件、`compose.yaml` 和本地运维脚本。
- 不包含真实凭证的 `.env.example`。
- 单元、契约和端到端测试代码，以及明确标记为虚构内容的测试夹具。
- SVG 品牌资源、架构与许可文档。
- `README.md`、`CHANGELOG.md`、`LICENSE`、`NOTICE` 和第三方许可清单。

## 必须留在本地

- `.env`、API Key、访问令牌、私钥、证书和任何真实 Cookie 文件。
- 下载的视频、音频、封面、字幕、转码结果和对象存储数据。
- PostgreSQL/SQLite 数据库、数据库转储、备份及消息队列数据。
- 真实任务记录、平台账号信息、发布回执和远端稿件数据。
- 日志、测试截图、Playwright 报告、一次性验收证据和临时文件。
- `node_modules`、Python 虚拟环境、编译输出、缓存和 IDE 配置。
- 工作过程中的位图渲染稿；正式品牌 SVG 可以提交。

## 发布前检查

1. 使用 `git status --ignored` 确认本地数据确实被忽略。
2. 只扫描 Git 将要提交的文件，不以工作目录扫描代替暂存区扫描。
3. 检查旧名称、绝对路径、邮箱、Cookie、密钥格式和大文件。
4. 运行前端类型检查与构建、Go 测试、Python 测试和本地端到端检查。
5. 检查提交和标签指向同一个已验证版本，再推送分支与标签。

如果凭证曾出现在日志、截图、聊天或提交历史中，单纯删除文件并不足够；必须在对应平台撤销并重新签发凭证。
